# 命令行基础速查

> 定位：双轨制的"运行/构建/部署/运维"侧速查；编辑与断点调试仍在 IDE。
> 已会 Linux 基础，这里只列计划内实际会用的命令 + WSL 专属坑，不重复入门内容。

# 主要思想

- **双轨制**：IDE 写代码/调试，终端运行/构建/部署/查日志。
- 环境：**WSL**（IDE 已配 Remote-WSL），手写 C 用 WSL 内 gcc；Java 刷题继续用 Windows 侧 javac/java。
- 手写 C 的验证闭环（阶段0 起每天用）：WSL 里 `gcc test.c -o test -Wall -g && ./test`。
- 危险区：`rm -rf`、`sudo`、生产环境命令，想清楚再敲。

# 分场景速查

## 手写 C 验证（现在起每天）
```bash
cd /mnt/d/你的代码目录        # 文件就在 D 盘，直接 cd 过去编译
gcc test.c -o test -Wall -g   # -Wall 开警告，-g 留调试信息
./test                        # 运行
```
- 单文件在 /mnt/d 上编译**性能无感**，IDE 编辑 + WSL 编译的组合就是最优解，不用搬文件。
- `-std=c99` 按需加。

## Java 本地验证（刷题）
```bash
javac Main.java && java Main      # Windows 终端（Git Bash / PowerShell 均可）
```
- **WSL 里的 JDK 和 Windows 的 JDK 是两套**。WSL 内要跑 javac 需在 WSL 里另装（`sudo apt install openjdk-17-jdk`）；刷题直接用 Windows 侧，别混。

## 项目期（阶段 2-3）
```bash
mvn clean package -DskipTests              # 构建
java -jar target/xxx.jar                   # 本地运行
ssh root@你的服务器IP                      # 上服务器
scp target/xxx.jar root@ip:/opt/           # 传包
nohup java -jar /opt/xxx.jar > app.log 2>&1 &   # 后台运行（或 systemctl）
tail -f app.log                            # 实时看日志（排查第一工具）
ps aux | grep java                         # 找进程
ss -tlnp | grep 8080                       # 查端口占用
curl http://localhost:8080/xxx             # 接口自测
```

## Git（WSL 内）
```bash
git status && git add -A && git commit -m "feat: xxx" && git push
git log --oneline -5
```
- WSL git 两个必设项（否则每次提交都提示文件被改）：
```bash
git config --global core.autocrlf input    # 行尾符：WSL 用 LF
git config --global core.filemode false    # 忽略权限位变化
```

# 文件放哪：D 盘 vs WSL（分水岭规则）

- **手写 C / 算法题（单文件）**：文件放 D 盘（/mnt/d），IDE 编辑 + 断点 + WSL 终端 gcc 编译——**当前方案就是最优**，单文件性能无感，别为了"用 WSL"搬文件。
- **Java 项目（阶段 2 起）**：本就应该在 Windows 侧（D 盘），用 Windows JDK/Maven 构建；**WSL 不参与 Java 构建**（双 JDK 是混乱之源），WSL 只负责部署时的 ssh/运维。
- **何时才需要文件进 WSL**：改用 VS Code Remote-WSL 做 Linux 环境开发，或踩到 drvfs 痛点（大型 repo 的 git status 慢、文件监视 watch 失效导致热重启不生效）——到点再说，现在不需要。
- 若断点调试在 /mnt/d 文件上报"路径不对/不生效"，再把练习目录挪进 WSL（`~/practice`），IDE 用 Remote-WSL 打开即可。
- 代码反正都 git push 到 GitHub，文件在哪个盘都有备份，不用焦虑。

# 易错点 / 红线

- `rm -rf` 和 `sudo`：确认路径再回车；服务器上敲错**不可逆**。
- gcc 报"文件不存在"先 `pwd` + `ls` 确认在哪个目录。
- 忘了 `-Wall` = 放弃编译器帮你抓低级错误（手写训练全靠它）。
- 后台进程用 `nohup ... &` 关终端不杀；单独 `&` 关终端会挂。
- 端口排查用 `ss -tlnp`（新版）→ 没有再用 `netstat -tlnp`。

# 日常闭环（把习惯钉进计划）

- 每天 2 个固定终端动作：① 手写 C 用 gcc 编译运行　② git 提交走命令行。
- 卡住就 `命令 --help` 或 `man 命令`，不背命令表。
- 阶段 3 部署上线全程终端操作（ssh/scp/nohup/tail），那两周自然形成肌肉记忆。
