#树 #二叉树 #遍历 #孩子兄弟
# 核心结论
树和二叉树通过**孩子兄弟表示法**（左孩子右兄弟）互相转换后，遍历有惊人的对应：

| 树的遍历 | 对应二叉树的遍历 |
|---|---|
| 先根遍历（先根，再依次遍历各子树） | **前序遍历**（根 → 左 → 右） |
| 后根遍历（先依次遍历各子树，最后根） | **中序遍历**（左 → 根 → 右） |

> ⚠️ 易错点：树的**后根遍历 ≠ 二叉树的后序遍历**，而是等于**中序遍历**。先根对前序、后根却对中序——不对称，考场上最容易记反的就是这个。

# 为什么能对上（孩子兄弟 + 转 45°）
树转二叉树时，每个节点只保留两条"线索"：**第一个孩子 → 左孩子**，**下一个兄弟 → 右孩子**。

画出来特别直观：

- 孩子的边是**竖直**的（父在上、子在下）
- 兄弟的边是**水平**的（哥在左、弟在右）

把这张"竖直 + 水平"的图**逆时针转 45°**：
- 竖直边 → 指向左下方 → 就是二叉树的**左孩子**边
- 水平边 → 指向右下方 → 就是二叉树的**右孩子**边

所以"**二叉树逆时针转 45° 可还原成原树**"这句话是真的——它俩本来就是同一张图的两个视角。

在这个"转 45°"的视角下看遍历：

- **先根遍历**：先输出根，再沿竖直边下钻到第一个孩子（走完它的整棵子树），再沿水平边右移访问后面的兄弟——走法和二叉树**前序**（根→左→右）完全同构；
- **后根遍历**：先钻进最左下的孩子，一路"先子树、后根"地访问，最后才回到根——访问节奏像二叉树**中序**：左子树 → 根 → 右子树，而这里"右子树"其实是兄弟链，所以**后根遍历 = 中序遍历**。

# 扫线记忆法（个人想象）
把二叉树想象成被一根"扫线"扫过，**线碰到哪个节点就输出哪个节点**：

- **前序**：像直线 `y=x` 移过去，碰到了就遍历，先经过右上、再经过左下；
- **中序**：像一根**竖线从左往右**移过去，碰到了就遍历——这条最直观：左子树在左边先被碰到，根在中间，右子树最后；
- **后序**：像直线 `x+y=0` 移过去，碰到了就遍历，先经过右下、再经过左上。

记忆钩子：二叉树转 45° 后，中序遍历的路径看起来很像"后序遍历"的走法（先孩子后根）——所以才有"树的后根遍历 = 二叉树的中序遍历"。

> 扫线只是帮助记忆的想象，不用太较真；更本质的直觉是"递归序"（每个节点被经过三次，第几次经过时输出就是哪种遍历），见 [[二叉树遍历]]。
